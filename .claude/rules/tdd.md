# TDD 규칙

> **경고: 이 규칙은 Rigid — 상황에 맞게 변형하지 마라.**  
> 예외를 허용하는 순간 이 규칙은 존재하지 않는 것과 같다.

---

## 0. 프로젝트별 규칙 우선 조항

이 파일은 **기본값(fallback)** 이다.  
프로젝트의 `CLAUDE.md` 또는 `AGENTS.md`에 TDD 관련 규칙이 명시되어 있으면, **그 규칙이 이 파일보다 우선한다.**  
이 파일의 규칙은 프로젝트별 규칙이 없을 때만 적용된다.

---

## 1. 적용 기준

### TDD를 반드시 적용하는 대상

| 대상 | 예시 |
|------|------|
| **비즈니스 로직** | 계산, 검증, 상태 전이 |
| **API 엔드포인트** | 요청 처리, 응답 포맷, 에러 핸들링 |
| **유틸리티 함수** | 파싱, 포맷팅, 변환 |
| **버그 수정** | 재현 테스트를 먼저 작성한 뒤 수정 |
| **커스텀 훅** | 상태 관리 로직, 사이드이펙트 |

### TDD가 불필요한 대상

| 대상 | 이유 |
|------|------|
| **타입 정의** | 컴파일러가 검증 |
| **설정 파일** | `vite.config.ts`, `tsconfig.json` 등 |
| **순수 UI 컴포넌트** | 로직 없는 렌더링 (스냅샷 테스트로 대체 가능) |
| **SQL / 마이그레이션** | 통합 테스트 또는 수동 검증 영역 |
| **상수·열거값** | 변경 불가 데이터 |

---

## 2. RED-GREEN-REFACTOR 사이클

### RED — 실패하는 테스트 먼저

- **하나의 동작 = 하나의 테스트.** 여러 동작을 하나의 테스트에 몰아 넣지 않는다.
- 테스트를 작성한 뒤 **반드시 실행해서 실패를 눈으로 확인한다.**
- 실패 이유가 **"기능 미구현"** 이어야 한다.  
  컴파일 오류나 설정 오류로 실패하면 그것부터 고친다.
- 테스트 이름은 "어떤 동작을 테스트하는가"를 한 문장으로 표현한다.

### GREEN — 최소한의 코드로 통과

- 테스트를 통과시키는 **최소한의 코드만 작성한다.**
- **YAGNI**: 지금 테스트가 요구하지 않는 기능은 작성하지 않는다.
- 신규 테스트뿐만 아니라 **기존 테스트 전체가 통과**하는지 확인한다.
- 아직 예쁘지 않아도 된다. 동작하면 된다.

### REFACTOR — 동작을 유지하며 코드를 정리

- 중복을 제거하고, 이름을 개선하고, 헬퍼를 추출한다.
- **Green 상태를 유지한다.** 리팩터 중 테스트가 깨지면 즉시 되돌린다.
- **새로운 동작을 추가하지 않는다.** 추가할 동작이 생기면 다음 RED로 넘긴다.

### 반복

리팩터가 끝나면 **다음 동작에 대한 RED로 돌아간다.**  
사이클을 건너뛰거나 순서를 바꾸지 않는다.

---

## 3. 삭제 강제 규칙

> 테스트 전에 프로덕션 코드를 먼저 작성했다면, **삭제하고 RED부터 재시작한다.**

- "테스트만 나중에 추가하면 된다"는 TDD가 아니다.
- **"참고용으로만 남긴다"는 변명도 금지한다.** 코드가 존재하면 영향을 준다.
- 삭제가 아깝다면: RED→GREEN으로 동일한 코드를 5분 안에 다시 만들 수 있다.

---

## 4. 변명 차단표

| 변명 | 반론 |
|------|------|
| "너무 단순해서 테스트가 불필요하다" | **단순한 로직이 가장 빠르게 테스트를 작성할 수 있다.** 단순함은 TDD를 건너뛸 이유가 아니라, 더 쉽게 할 수 있다는 신호다. |
| "나중에 테스트를 추가하겠다" | **나중은 오지 않는다.** 코드가 존재하면 수정이 두려워지고, 테스트 추가는 점점 미뤄진다. 지금이 가장 쉬운 시점이다. |
| "시간이 없다" | **테스트 없이 작성하면 디버깅, 재작업, 회귀 방지에 더 많은 시간이 든다.** TDD는 속도를 늦추지 않는다 — 장기적으로 빠르게 한다. |
| "이미 작성한 코드를 삭제하면 낭비다" | **잘못된 순서로 만든 코드는 부채다.** 삭제하고 다시 작성하는 비용은 RED→GREEN 한 사이클이면 충분하다. |
| "프로토타입이라 나중에 버릴 코드다" | **프로토타입이 프로덕션이 된 사례는 셀 수 없다.** 버릴 코드라면 지금 버려라. 계속 쓸 코드라면 TDD를 적용해라. |
